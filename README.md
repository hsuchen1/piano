# 萬能鋼琴演奏 (Interactive Piano Studio)

[![GitHub Pages Deploy](https://github.com/hsuchen1/piano/actions/workflows/deploy.yml/badge.svg)](https://github.com/hsuchen1/piano/actions/workflows/deploy.yml)

**線上演示:** [https://hsuchen1.github.io/piano/](https://hsuchen1.github.io/piano/)

歡迎來到互動鋼琴工作室！這是一款功能強大的網頁工具，讓您不只能彈奏鋼琴，還能創造出豐富的背景伴奏，並透過 AI 與多種效果精雕細琢您的音樂。本應用程式亦為漸進式網頁應用程式 (PWA)，支援離線使用並可安裝至主畫面。

## ✨ 主要功能

### 1. 彈奏虛擬鋼琴
*   **多種輸入方式：**
    *   **滑鼠/觸控：** 直接點擊或觸碰螢幕上的琴鍵即可發聲。
    *   **電腦鍵盤：**
        *   中下排 (Z, S, X, D...) 對應一個八度。
        *   中上排 (Q, 2, W, 3...) 對應高一個八度。
        *   **空白鍵：** 隨時播放或停止伴奏。
        *   完整按鍵對應定義於 `src/constants.ts` 的 `KEY_MAPPING`。
*   **視覺化回饋：** 按下的琴鍵會高亮顯示。

### 2. 核心設定
*   **移調控制：** 使用 `+` 和 `-` 按鈕即時升高或降低所有琴鍵的音高，讓您用 C 調的指法彈奏任何調性。
*   **主鍵盤設定：**
    *   **音色：** 共 7 種——古典平台鋼琴、真實平台鋼琴、吉他、弦樂合奏、明亮直立鋼琴、電鋼琴、基本合成器。取樣類音色（真實平台鋼琴、吉他、弦樂合奏）首次選擇時需要短暫載入。
    *   **音量：** 調整您手動彈奏的琴鍵音量。
    *   **顯示伴奏音符：** 開啟後，伴奏正在彈奏的音符會同步在琴鍵上以藍色顯示。

### 3. 建立您的和弦進行
*   **新增和弦：** 選擇根音與和弦類型，然後點擊「新增和弦」。支援 18 種和弦類型：
    三和弦 (`Maj`、`min`、`aug`、`sus2`、`sus4`、`5`)、
    六和弦 (`6`、`m6`)、
    七和弦 (`7`、`m7`、`Maj7`、`dim7`、`m7b5`)、
    九和弦與變化音 (`Maj9`、`m9`、`9`、`7#9`、`7b9`)。
*   **編輯和弦進行：**
    *   **刪除：** 點擊和弦右側的紅色 `X` 按鈕。
    *   **轉位：** 點擊和弦旁的 `0, 1, 2...` 按鈕切換轉位。按鈕數量會依和弦組成音數自動調整。
    *   **重新排序：** 按住並拖曳和弦到新位置。
    *   **清除：** 一次清除所有和弦。
*   **儲存與載入：** 儲存至瀏覽器本機 (localStorage)。一份存檔會完整記錄：
    *   和弦進行（含每個和弦的轉位）
    *   所有伴奏層的樂器、音量、節奏型態與自訂節奏格
    *   鼓組的啟用狀態、音量、風格與自訂鼓點
    *   貝斯的啟用狀態、音量、音色、風格與 AI 貝斯線
    *   速度 (BPM)、移調、主鍵盤音量與音色
    *   殘響、延遲、搖擺律動
*   儲存時若名稱與既有存檔重複，會先詢問是否覆寫。

### 4. AI 智慧創作 (Gemini API)
所有 AI 功能都需要您自己的 Google Gemini API 金鑰。金鑰只會存放在您自己瀏覽器的 localStorage 中，不會上傳到任何伺服器，也不會被打包進網站。請在「API 金鑰設定」面板中輸入。

*   **AI 和弦生成：** 用文字描述風格或情緒，AI 產生一組全新的和弦進行（會取代目前內容，執行前會先確認）。
*   **AI 風格轉換：** 將現有進行重新配置成指定風格（例如爵士、8-bit），保持和弦數量不變。
*   **AI 智慧轉位：** 分析整段進行並自動選擇轉位，讓最高音的旋律線更平滑、音高更穩定。
*   **AI 鼓組生成：** 在自訂鼓組編輯器中，為單一小節產生 16 步鼓點。
*   **AI 貝斯線生成：** 為整段和弦進行創作一條完整的貝斯線。

### 5. 設計您的伴奏
*   **主控制：** 播放/停止、速度 (40–240 BPM，附節拍指示燈)、音訊引擎狀態提示。
*   **和弦 (Chords) 分頁：**
    *   支援**多個伴奏層**，例如一層鋼琴加一層弦樂。
    *   每層可獨立設定音量、樂器與節奏型態。
    *   選「自訂」後會出現**自訂節奏編輯器**，可為每個和弦的 4 拍分別設定音符時值（全音符到十六分音符，或關閉）。
*   **鼓組 (Drums) 分頁：**
    *   10 種預設風格：搖滾、流行/放克、爵士搖擺、拉丁、EDM、抒情、慢板流行、嘻哈、巴薩諾瓦、雷鬼。
    *   選「自訂」後會出現**自訂鼓點編輯器**：為每個和弦、5 種鼓樂器（大鼓、小鼓、閉合鈸、筒鼓、碎音鈸）的 4 拍 × 4 個十六分細分逐格設定，並可複製／貼上整個小節的鼓點。
*   **貝斯 (Bass) 分頁：** 啟用後可設定音量、音色（電貝斯、合成貝斯、木貝斯、Pop Pulse）與 7 種風格（根音、根音與五音、簡單琶音、簡易行走貝斯、旋律行走貝斯、放克 Slap、AI 生成）。
*   **效果 (Effects) 分頁：** 影響所有聲音（含手動彈奏）。
    *   **殘響 (Reverb)：** 增加空間感。
    *   **延遲 (Delay)：** 產生回音效果。
    *   **搖擺律動 (Swing)：** 讓節奏帶有搖擺感，常用於爵士樂。

## 🛠️ 技術棧

*   **前端框架：** [React](https://reactjs.org/) 19
*   **建置工具：** [Vite](https://vitejs.dev/) 6
*   **程式語言：** [TypeScript](https://www.typescriptlang.org/)
*   **音訊處理與排程：** [Tone.js](https://tonejs.github.io/)
*   **樣式：** [Tailwind CSS](https://tailwindcss.com/) 3（於建置階段編譯，不使用 CDN，因此離線時樣式仍然正常）

*   **品質檢查：** ESLint、TypeScript、[Vitest](https://vitest.dev/)

## 🚀 開始使用

### 先決條件

*   [Node.js](https://nodejs.org/) `^20.19.0 || ^22.13.0 || >=24`（建議使用 22 LTS，與 CI 一致）
*   [npm](https://www.npmjs.com/)

### 安裝

```bash
git clone https://github.com/hsuchen1/piano.git
cd piano
npm install
```

若要重現 CI 的安裝結果，請使用 `npm ci`。

### 可用指令

| 指令 | 說明 |
| --- | --- |
| `npm run dev` | 啟動 Vite 開發伺服器（預設 `http://localhost:5173`） |
| `npm run build` | 先型別檢查，再輸出生產版本至 `dist` |
| `npm run preview` | 在本機預覽 `dist` 的生產版本 |
| `npm run typecheck` | 只執行 TypeScript 型別檢查 |
| `npm run lint` | 執行 ESLint |
| `npm test` | 執行 Vitest 測試 |
| `npm run test:watch` | 以 watch 模式執行測試 |

### AI 功能的本機開發

在專案根目錄建立 `.env.local`：

```
VITE_GEMINI_API_KEY=your-key-here
```

這只是開發時的便利設定，用來預先填入金鑰。程式碼中以 `import.meta.env.DEV` 包住這段讀取，因此**production 建置絕不會把金鑰打包進去**。部署後的使用者一律在 UI 中輸入自己的金鑰。

`.env.local` 已列於 `.gitignore`，請勿提交。

## ⌨️ 鍵盤控制

電腦鍵盤配置模擬真實鋼琴佈局，完整對應定義於 `src/constants.ts` 的 `KEY_MAPPING`。空白鍵可播放／停止伴奏。當焦點位於文字輸入框、下拉選單等表單元件時，鍵盤彈奏會自動停用以避免衝突。若視窗在按住琴鍵時失去焦點，所有按住的音符會自動釋放。

## ☁️ 部署

透過 GitHub Actions 自動部署至 GitHub Pages，設定位於 `.github/workflows/deploy.yml`。

流程分為兩個階段：`verify` 執行 ESLint、型別檢查與測試；只有在 `verify` 通過後，`deploy` 才會建置並發佈。Pull request 只會執行 `verify`，不會動到線上網站。

若需手動發佈，`npm run deploy` 會建置後透過 `gh-pages` 推送 `dist`。一般情況建議交由上述 CI 流程處理。
